## 3. Validator chain, tests and probes

- The documented commands (package sections 3 and 11) reproduce every expected count and digest. The
  changed-index list is `[97, 98, 102]`.
- Focused tests (disposable `test_ctug_registration_<random>` MySQL): 97/97 OK. These were 46 v2,
  17 v2.1 static, 16 v2.2 static, 9 v2.1 runtime and 9 v2.2 runtime tests. D-85 module
  (test_wf0301_d85_p3b_compatibility): 16/16 OK.
- 39 genuine in-memory tamper probes, written separately from the author's tests, were all rejected
  with the expected error class. Two further probes mocked the second read (`v2.read_manifest`). At
  `edbaf9f`, the standalone v2.1 probe accepted the substituted content with a non-pinned digest,
  exposing F-1, and the v2.2-chain probe was rejected with an effective-digest mismatch. (D-1: earlier
  wording of this record overstated the count as "41 … all rejected" and then as "40 rejected".) The
  39 genuine probes covered addendum byte, CRLF and newline edits; the delta changing
  another code, an unapproved role, a duplicate, missing or reordered operation, a third move, an extra
  field, a forged base digest or a forged review status; the v2.0 manifest with an edited permission
  attribute, a duplicate or missing binding, an extra byte or a lone CR; invalid v2.0 source pins (AR-2,
  SRS); an altered v2.1 pin constant or required effective digest; and guarantee mutations (Superuser
  bypass, Deny precedence, delegation, framework privilege, readiness, eligibility, governance code
  binding, Admin regaining a moved code, Admin gaining diagnostics.read, a WF-02 binding moved).
- A read-only query of `ctug_workspace` (in a READ ONLY transaction) found 0 Technical Super Admin roles,
  0 `access_control.*` permissions and 0 Technical Super Admin assignments. The only bound codes are the
  six registration-review and school-account codes.
- No production module imports validation_v2_1 or validation_v2_2. framework_roles and P3B/P4 read v2.
  The protected P3B/P4 commands, framework_roles, role_assignment, role_management, services and
  technical_admin have no diff since `0da2182`, so D-102 is not activated.
