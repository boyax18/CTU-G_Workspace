# WF-01.02 — Adopt Student error feedback and response

16 November 2026 (Asia/Manila). Owner instruction: “make it consistent, adopt the student error feedback/response.” This supersedes the earlier Instructor-specific conflict copy, four-action panel and extra OTP error presentation. Core Instructor OTP, Staff ID, role/field restrictions, review boundaries and abuse controls are retained.

Current spec: [catalogue](../CTU-G_Workspace_System_Workflow_Catalogue.md). Prior OTP implementation/evidence: [historical foundation](WF-01.02_Instructor_OTP_Implementation.md).

## Shared current behavior

| Area | Student and Instructor behavior |
| --- | --- |
| Conflict HTTP/code/message | HTTP 409, code conflict, “We could not complete this registration. Please check your information or contact support.” Before/after OTP and HTML/untrusted 409 use this same safe text. No conflicting-field disclosure. |
| Form feedback | Same accessible error notice, request reference, check-details/wait-for-review guidance and Sign in link to /. Only the ID label differs: School ID or Staff ID. Safe input retained; passwords cleared. |
| Removed Instructor panel | No separate Log in, password-reset/unavailable paragraph, Continue your registration button or contact-action block. The redundant disabled continuation control is removed. |
| API errors | Same error envelope: code/message/request_id, optional safe field errors/retry hints and common stage counters. No Instructor-only requested_role, support_contact, password_reset_enabled, can_continue, email or otp_expires_in in errors. Successful owned-stage replies retain role context where needed to preserve the actual original role. |
| OTP feedback | Same generic saved-registration email reference, attempts counter, expiry error with Resend code, resend countdown, Cancel registration, security refresh, status check and restart presentation. Instructor-only recipient/spam/wrong-email/time-to-expiry blocks are removed. Actual backend OTP/stage expiry, attempts and mail-failure recovery are unchanged. |
| Saved attempt | Matching/nonconflicting owned attempts resume the immutable original stage without new mail. Changed submitted identities that conflict return shared 409 while preserving the valid original stage/cookie; correction allows resuming it. No cross-browser resume/cancel. |
| Storage failures | Genuine identity/reservation collisions remain generic 409; unrelated duplicate-key storage failures return safe 503 with rollback for both roles. This corrects the legacy Student misclassification to conform to WF-01.01's existing transaction-failure contract; its approved wording/main flow are unchanged. |

Staff ID remains 1–7 digits in existing school_id; no Instructor school information is displayed/accepted. OTP still precedes atomic Pending/inactive account/profile/proof creation, with no assigned role/login. Existing Instructor identity/IP throttles, fixed expiry and unique stage/account constraints remain in force. Password recovery is neither enabled nor bypassed. Official support contact remains an owner-input item; registration feedback now uses Student's generic contact-support wording instead of the earlier role-specific configured action. No official contact was invented.
