## 2. Reviewed schema contract

| Element | V2 contract | Engineering requirement before migration |
| --- | --- | --- |
| Outbox identity | `outbox_id bigint` auto-increment PK | Django `BigAutoField`, MySQL `BIGINT`; confirm generated SQL |
| Decision link | `decision_audit_log_id int NOT NULL UNIQUE` | `OneToOneField` to `AccessAuditLog` with `db_column` and `on_delete=PROTECT`; never CASCADE |
| Template | `template_code varchar(64)`, `template_version int` | Only `registration.approved` / `registration.rejected`; pin template version on retries |
| Recipient | `encrypted_recipient varbinary(1024)` and 12-byte nonce | Authenticated ciphertext and tag; zero plaintext addresses stored in this table |
| Key envelope | `wrapped_data_key varbinary(512)`, `encryption_key_version varchar(64)` | Only wrapped per-event data key stored; master wrapping key outside DB and Git |
| Secure disposal | `recipient_erased_at datetime` | Clear ciphertext, nonce, wrapped key and key ID together under an approved retention schedule |
| Delivery | `Pending`, `Leased`, `Retry`, `Delivered`, `Dead` | Enforce allowed transitions and coherent nullable fields in service and DB constraints when feasible |
| Retry mechanics | attempts, next due time, lease token and expiry | Atomic claims; bounded retries; stale-token updates rejected |
| Diagnostics | `last_failure_code varchar(64)`, timestamps | Allowlisted error codes only; no exception messages, SMTP responses, addresses or secrets |
| Indexes | (`delivery_status`,`next_attempt_at`), (`delivery_status`,`lease_expires_at`) | Verify intended query plans and exact index names in migration review |

**Definition:** `Delivered` means accepted by the configured sending backend; it does **not** guarantee arrival in the recipient's inbox.

### Referential and validation invariants

- Each outbox row references **one exactly identified** `access_audit_logs` row, and at most one outbox row may reference that audit ID. Enforce action/template correspondence (`account.registration.approve` ↔ `registration.approved`; `account.registration.reject` ↔ `registration.rejected`) in trusted service code.
- `Pending`/`Retry` require a due timestamp; `Leased` requires a lease token and expiry; `Delivered`/`Dead` must have no active lease or due timestamp. `attempt_count >= 0` and is capped by worker policy. Missing or invalid historical recipient results in `Dead`, with absent cryptographic fields and `recipient_unavailable` code.
- When ciphertext exists, nonce, wrapped key and nonsecret key version are all present. After erasure, all four are null and `recipient_erased_at` is populated. Do not mix partially erased key material and decryptable ciphertext.
- All scheduled and recorded instants use UTC. Inspect `datetime`/`timestamp` semantics, connection timezone and SQL generated by the actual Django/MySQL versions before approving a migration.

## 3. Required code design (not yet implemented)

1. Keep existing Admin role, exact effective permission, Deny precedence, service-availability and account eligibility checks.
2. The current `record_access_audit()` returns `None`. Introduce a **narrowly audited receipt-capable sibling** that shares the same validation and append-only behavior but returns the exact inserted audit PK. Do not query a latest row or weaken the original helper's return contract.
3. Within the same authorized MySQL `READ COMMITTED` decision transaction, update the account, assign its base role if approved, insert the audit event, and insert its unique outbox row. If encryption or insertion fails in outbox mode, roll back the entire decision. Do not send SMTP mail inside the transaction.
4. Use mutually exclusive modes: existing AR-6C5A best-effort `transaction.on_commit` sending **or** durable outbox sending, never both for the same decision.
5. Start a separately gated worker that claims due rows in short database transactions and sends outside transactions. Lease completion must match the current lease token. Reclaim expired leases safely.
6. Apply bounded retries for transient failures; mark permanent or exhausted failures `Dead`; log only safe codes and nonpersonal metrics.

**External email limitation:** A crash after provider acceptance and before acknowledgement can produce repeat emails. The design permits at-least-once attempts, not exactly-once delivery.

## 4. Proposed initial worker defaults — reviewable, not approved policy

| Setting | Engineering starting point | Reason |
| --- | --- | --- |
| Worker cadence | Check due rows once per minute | Development baseline, configurable |
| Maximum attempts | 5 total attempts | Bounded retries, not unlimited delivery |
| Retry delays | 1, 5, 15, 60 minutes, each with bounded jitter | Avoid synchronized retry storms |
| Lease length | 2 minutes, only if network timeouts are shorter | Recover hung/crashed claims while limiting duplicate sends |
| Provider timeout | Strictly shorter than lease lifetime | Reduce simultaneous retry risk |
| Alerting | Alert on `Dead` rows and stale lease backlog | Failures require restricted operator follow-up |
| Encryption | Authenticated per-event encryption with 256-bit data key; external wrapping key | Limits database-exposure impact |
| Retention | **Unset** pending institutional approval | Do not invent a legal retention period |

Validate actual MySQL support for `SELECT ... FOR UPDATE SKIP LOCKED` using isolated integration tests and apply identical row-lock ordering rules as trusted review writers. If unavailable, do **not** approximate with unsafe concurrent fetches.

## 6. Safe implementation sequence after schema approval

**Gate A — Owner approval:** Explicitly approve the v2 proposal and agreed schema constraints. Confirm the local official ERD checksum and make a reviewed diff; retain a backup. No implicit schema authorization from earlier approval of the *idea*.

**Gate B — Model/migration development:** Implement the Django model and a migration in a branch, add SQL/constraint review, test migration only against an isolated MySQL test database. Check DBML-to-model fidelity. Do not modify the user's main development database without a further go-ahead.

**Gate C — Atomic write path:** Add receipt-capable audit writer, envelope encryption boundary, outbox insertion and rollback tests. Keep review API, new outbox flag and SMTP disabled by default.

**Gate D — Worker:** Add a separately gated retry worker, concurrency/lease tests, key failure/rotation tests, and recipient-erasure tests once a retention schedule is approved.

**Gate E — Release readiness:** Security review, logging/metrics review, email sender and address-verification decisions, operational key access, and campus governance approval. Only then consider activation.
