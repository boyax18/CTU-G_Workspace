# WF-03.01 D-113 — Active role context policy (staged, NOT tested)

Implementation scope: optional session-selected role, *not* an assignment and not a permission grant. Current production mode remains unchanged. The isolated review modes have an independent, default-off switch. Only the server selects and validates role IDs. Each request recomputes stored, active roles, permissions, services and appointment evidence; no role or grant from the browser is trusted.

- Student or Instructor context permits only actual selected-role grants. The selected Admin context permits actual Admin grants but no Technical Super Admin grants. The selected Technical Super Admin context permits its own actual grants plus stored grants of an *also-assigned* active Admin role. This preserves the approved Super Admin → School Admin operational inheritance without a hardcoded permission bypass.
- Role-specific permissions come only from active RolePermission rows. AccountPermission Deny remains global. AccountPermission Grant is intentionally not used while role-context selection is enabled because the current schema cannot bind an override to a role. WF-03.03 must reconcile a safe scope/precedence design before enabling this feature.
- An invalid, removed, expired-appointment ordinary role or nonexistent session selection results in no active role and zero effective permissions until an eligible role is selected. Ordinary-role selection is denied while the D-111 continuous appointment gate is OFF.
- The selected role ID is stored in the existing protected Django session (HttpOnly cookie); no password, permission or attestation is stored. The switch requires CSRF and a fresh approved, active session. All mutations remain separately authorized; the UI is a hint only. Role switching alone does not write access-audit role-assignment records because it does not change assignments.
- Normal config.settings and config.urls mount no switch and no role-context middleware. Only review_local and review_sandbox append the middleware and mount the endpoint, independently disabled. Protected executor mode has not been reconciled with request-role scoping; DO NOT enable for that mode without a full boundary review.
- Migration D-110 remains unapplied; appointment reviewer and S0→S1 governance policy remain open. These are **release blockers**, not waived by an accelerated development schedule.

**Deferred tests:** CSRF, backend role grant isolation, direct Grant/Deny, inheritance, stale/revoked context, ordinary expiry/revocation, simultaneous browser sessions, multi-tab selection, session revocation, protected API checks, protected executor parity, UI keyboard/accessibility, and full WF-03 regression. No test execution or final Human Approval has occurred.
