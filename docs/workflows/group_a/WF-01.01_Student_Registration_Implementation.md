## Alternatives and operational behavior

- Resend: row-locked, 60-second cooldown, at most three resends. The old code is invalidated, and a resend cannot choose the immediately preceding numeric code again. Failed-attempt count and fixed stage deadline do not reset.
- Duplicate stage: never overwrite the earlier details. The original browser's opaque cookie proves possession and resumes that earlier stage. Another browser knowing only School ID/email gets the generic conflict message. There is no separate resume button/link, per the user's 16 November instruction. Student form's primary button reads “Proceed Email Verification”; Instructor's existing submission behavior/label remains unchanged. There is no unauthenticated cross-device recovery shortcut; without the cookie, wait for stage expiry or use the original browser to cancel.
- Cancel: CSRF-protected, original cookie required; deletes the stage and invalidates the code without affecting any account.
- Failed/uncertain mail delivery: return a genuine failure, clear the uncertain OTP digest, retain encrypted stage for bounded resend and expose no mail exception/recipient/code. Initial send failure still sets the ownership cookie for recovery. Resend failures consume the resend/cooldown budget.
- Abandonment: verification rejects expired stages immediately. Purge command removes only expired stages; --watch runs every 60 seconds. Active stages are not deleted. A local cleanup worker is running for this session; production needs a supervised worker/scheduled command. It can remove expired data up to one polling interval after the deadline.
- Request protection: original registration IP limits retained. OTP mutations have separate 30/minute and 200/day IP limits; the per-stage resend/attempt limits remain authoritative across processes.

Encryption key is purpose-derived from STUDENT_REGISTRATION_STAGING_KEY, falling back to the existing Django SECRET_KEY. Production should provision a separate random key outside Git, retain it while stages are live, and coordinate rotation with stage expiry. A short/unavailable key fails closed. Install the pinned dependency from backend/requirements-registration.txt if it is not already installed.

## API and local operation

| Method | Path | Behavior |
| --- | --- | --- |
| POST | /api/v1/auth/register/ | Student: stage/send and return verification_required; original cookie resumes existing_verification. Instructor: existing acknowledgement. |
| GET | /api/v1/auth/register/verification/ | Cookie-bound stage summary only; no identity or secret in response. Missing/expired attempt returns 410. |
| POST | /api/v1/auth/register/verify/ | Body contains only six-digit code; atomically finalize on success. |
| POST | /api/v1/auth/register/resend/ | Empty JSON object; bounded resend. |
| POST | /api/v1/auth/register/cancel/ | Empty JSON object; delete owned stage. |
